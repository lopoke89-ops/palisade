## 1. Buy Supply Cases with skill points (3 SP = 1 case)
**Goal:** players can trade unspent skill points for Supply Cases in the Locker, at 3 SP per case.

**Decided by Big U:**
- There is **no cap** on how many cases can be bought.
- **No-account players get the same trade** in their browser locker.

**Server (accounts; needs approval before applying):**
- Add an RPC, e.g. `public.buy_case_sp(p_rev integer default null)`.
- Model it on the live `buy_case`: `private.require_user()` (identity and ban check), row lock, `private.check_rev`.
- Behavior:
  - Refuse unless the locker's **unspent** skill points are ≥ 3. Points already spent in the skill tree must never be touched.
  - On success: SP − 3, Supply Cases + 1, `rev + 1`. Return `private.locker_out`.
  - `sp_total` stays unchanged, so lifetime SP records and skill-tree limits keep their meaning. Verify how `sp`, `sp_total`, `skills`, `skill_buy` and `skill_respec` interact before finalizing, and document the choice. Make sure a respec after buying cases can't refund SP that was spent on cases.
- Grants: `authenticated` only; `anon` denied.
- PGlite tests: success, fewer than 3 SP refused, repeated purchases (no cap), stale revision refused, banned user refused, skill-tree spend unaffected, respec still correct afterwards, anon denied.

**Client:**
- Add a "3 SKILL POINTS → SUPPLY CASE" button next to the existing Supply Case OPEN control in the Locker case panel, showing the player's SP.
- Accounts call the RPC. **No-account players** spend from the local locker with the same rules, going through the same `grant`/`caseAdd` path and saved with `saveLocker`.
- Disable it (with a reason) when below 3 SP, or when an account is offline.
- Confirm before spending, then refresh the locker in place, keeping focus and scroll.
- Tests:
  - Account mock (pattern: `ultimate_cloud.js`): success, several purchases in a row, too few SP, offline message.
  - No-account: SP − 3, case + 1, persists across reload, and a respec doesn't refund spent SP.

## 2. In-game UI refresh (landscape first)
**Goal:** more play area, especially in phone landscape (844×390 and similar).
- **Boss health meter:** it takes too much screen space in landscape. Make it compact there: a thinner bar across the top center with the name inline, and XL two-boss raids stacked tightly or combined. Keep portrait readable.
- **Team health bars** (YOU / DELGADO / CORE and crewmates) move to the **bottom-left corner**. They must not collide with the move stick, the chat button, the build kit column on the right, or safe-area insets.
- Keep all existing element IDs; tests and the controller focus map depend on them.
- Check 390×844, 844×390, 932×430 and 1280×800 with 1, 3 and 6 players, a normal raid and an XL two-boss raid.
- Tests: add a HUD layout test that asserts no overlaps between HUD rectangles and the touch sticks or kit in both orientations. Save screenshots.

## 3. Enable / disable in-game tips
- Add a **Show tips during games** toggle to the Screen card in Settings. It appears in both the menu Settings page and the in-game settings panel, because they share the cards.
- Save it in `cfg` (default **on** for new players) and include it in save export/import.
- When off, `setTip` gameplay hints don't show. Toasts that carry real information (boss arrivals, IS BACK, rewards, errors) always show.
- Tests: tips hidden when off, important toasts still shown, the setting persists across reload.
