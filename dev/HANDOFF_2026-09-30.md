## How Big U works (follow these)

- **Big U (lopoke89) owns the game and approves.** Merges to `main` and any server migration need his explicit approval ("approve all", "push it"). Show before you ship: build on the branch, send screenshots at desktop, phone portrait and phone landscape, then merge.
- For a new feature, first write a **work order** in `dev/plans/` that records his decisions, get it approved, then say "execute".
- Releases are versioned `v0.9.x.y`. Each one gets:
  - the footer version in `dev/src/page.html` (`<p class="foot">v…`);
  - a section in `dev/STATUS.md`;
  - screenshots in `dev/evidence/<version>/`;
  - a squash-merged PR titled `vX: Name (#n)`.
- Commit and push to the working branch often; a stop hook checks for uncommitted changes.

## Build, source and test mechanics

- **Source** lives in `dev/src/`: `page.html`, `style.css`, and `js/*.js`. The JS files are concatenated **in file-name order** into one IIFE.
- **Build** with `python3 dev/build.py`. It writes `index.html`, `sw.js` and `debug.html` (gitignored) at the repo root. Never hand-edit the generated files.
- **After each build** run `git checkout -- '*.png'`; the build touches tracked PNGs.
- **Comment trap:** several source files have very long lines. A `// comment` put in the middle of a line swallows the code after it. This broke things twice: `extraBoss` in v0.9.4.0, and a test in v0.9.5.0. Put comments on their own line or at the very end.
- **Debug hooks:** `window.__pal` is defined on one long line in `dev/src/js/22-loop-menus.js`. Add new hooks there when a test needs them.
- **Tests:** Playwright scripts in `dev/test/`.
  - Set `CHROMIUM=/opt/pw-browsers/chromium-1194/chrome-linux/chrome` in this cloud container.
  - Run the full suite with `bash dev/test/run_all.sh`. The file isn't executable. It takes over 10 minutes, so give background runs a long timeout.
  - The script starts a static server on :8080 at the repo root and `peer-server.js` on :9000 (PeerJS).
  - SQL tests use PGlite and fake Supabase; no internet is needed.
  - A single test: `cd dev/test && node <name>.js`.
- **`run_all.sh` pass rule, as of this session:** a test passes only if it exits 0, its output shows `errors: none` (or equivalent), and it has no `Error:`, `TypeError` or `timed out` lines. Before this session the exit code was ignored.
- **Menu review tool:** `node dev/test/menu_audit.js`, not pass/fail. It screenshots 14 menu pages at 1440×900, 1280×720, 390×844 and 844×390 into `dev/test/out/menu_audit/`, with a `report.json` of layout measurements: overflow, small tap targets, tiny text.
- **Server migrations:**
  - Write them in `dev/supabase/migrations/`.
  - Build each one from the **live** function text; pull it with `pg_get_functiondef`.
  - Test it in PGlite, and apply only after Big U approves.
  - After applying, rename the file to the version Supabase recorded, and check advisors.

### 2. Blitzkrieg Rush: v0.9.4.0 (PR #8, live)

**Work order:** `dev/plans/blitzkrieg-rush-work-order.md` records every decision; its commit history shows each round. **Full release notes:** the v0.9.4.0 section of `dev/STATUS.md`.

**Big U's decisions:**

- **The mode:**
  - 15 raids, then the Final Blitz: a 5-minute clock with a boss every 30 s. At most 4 bosses are alive at once, so the boss bars don't clutter.
  - The last 60 s is an individual evacuation. You stand 3 s in a 3-tile ring (radius 1.5) to extract.
  - Downed players can make the evac only if they are revived.
  - The core no longer decides the result once the evac starts.
- **Left behind:**
  - You lose and keep half your cases and shards. Odd counts round up first: `ceil(n/2)`.
  - Rounds, boss kills, skill points and milestones are never halved.
  - It affects only you, not your squadmates.
- **Five variant bosses,** with their own names and 2 Blitzkrieg Cases each:
  - **Harbinger** (Ferryman): arcing missiles you can dodge.
  - **Blue Butcher:** a teal arc that breaks wood and brick walls and leaves blue dust (~0.5 s).
  - **Arsonist** (Demolisher): a napalm chain, 10 s patches, burns metal at twice regular fire's rate.
  - **Tempest** (Stormcaller): the normal beam, twice.
  - **Bulldozer** (Foreman): no digging; charges fast and is dazed 3 s when he hits a wall.
- **Modifiers:**
  - Removed: Boss Rush.
  - New: Hot LZ, Double Time, Artillery Barrage, Lockdown, Scorched Earth.
  - Nightmare stays, without surprise bosses.
- **BLITZKRIEG RUSH milestone ladder:**
  - Counts total Blitzkrieg bosses killed in the mode, credited to everyone in the match.
  - At 10 / 25 / 50 / 75 / 100: Devil Horns, Blue Arc tracer, Blue Butcher skin, Hell Portal kill FX, Demon skin (Gold).
- **Blitzkrieg Case** (14 shards): themed tracers and kill FX, the Scorched Front background, and the animated **Hellgate** background.

**Code map:**

### 3. Menu audit (review only)

Big U asked to see every menu page on desktop and on phones in both orientations before any change. `dev/test/menu_audit.js` was written for this.

**Findings:**
- PLAY was buried under the modifiers.
- Landscape phones were barely usable: the character was off-screen and labels wrapped.
- In portrait, the map picker came after START.
- The middle of the desktop screen was wasted, and headings were redundant.
- Settings cards were uneven, with small sliders.
- Text was tiny (9-10 px).
- The Milestones tab ran about 12 screens long in landscape.

**Big U's answers:**
1. Keep the character centrepiece.
2. One PLAY button with the setup behind it, "intuitive menu design that just makes sense".
3. Light touch on the Locker: "I like what we have… just change anything that can make the locker better".

### 4. Menu overhaul: v0.9.5.0 (PR #9, live)

Full notes are in the v0.9.5.0 section of `dev/STATUS.md`. Screenshots are in `dev/evidence/v0.9.5.0/`. No protocol change and no migration.

**PLAY (the old Solo page, `#pg-solo`):**
- Four tappable lines, built as `.setupRow` buttons in `#homeRows`: MAP, LENGTH, JOB, MODIFIERS. Then one PLAY button (`#startBtn.playBtn`).
- A line opens the **setup sheet** `#setupSheet` on its tab: map, rules, job or mods.
- The right column `#homeSide` holds cards for the new mode (TRY IT), cases ready to open, the next unlock with a progress bar, and skill points.
- The code is in the new file `dev/src/js/19c-home.js`: `setupRowsFor`, `fillRows`, `renderHome`, `openSetup`/`setupTab`/`closeSetup`, `renderSetupJobs`, `renderHomeSide`, `nextUnlock`.

**One sheet for three contexts,** held in `SETUP.kind` in `19b-social-lobby.js`:
- `home`: solo.
- `host`: the HOST A ROOM card.
- `room`: the lobby, host only; guests see the lines read-only.
- `#mapPanel` was moved into the sheet at load time: `$('ssMap').append($('mapPanel'))`. `#soloMods` renders modifiers for whichever kind is open.
- Closing the sheet calls `broadcastLobby()` for a host. Escape, a backdrop tap or DONE (`#setupDone`) closes it.

**MULTIPLAYER (`#pg-multi`):**
- Name, then a JOIN A CREW card (`#mCode`, `#joinBtn`), then a HOST A ROOM card (`#pvSeg` co-op / base / FFA, `#hostRows`, `#hostBtn`), then OPEN GAMES.
- The old `data-mc`/`data-mm`/`data-md` segs are kept in a hidden div (`tabindex=-1`) so older code paths still work.

**Room (`#pg-lobby`):**
- The code, `#shareBtn` and `#lStart` come first. Then `#roomRows`, YOUR JOB (`#lJobs`), `#lOneJob`, CREW, `#lModsBox` (hidden for the host, who uses the sheet), CHAT and `#lLeave`.

**Nav:**
- PLAY, MULTIPLAYER, LOCKER, SKILLS, CLASSES, SETTINGS, each with an inline SVG icon (`svg.nIco`).
- Counts show in `.nBadge` elements. The labels sit in `.nLbl` and never change; `navBadge()` in `19-accounts.js` does this.
- **Phone portrait (≤700 px):** a fixed bottom tab bar, with PLAY pinned above it by `position:fixed` and a fade.
- **Phone landscape (`max-height:500px`):** a slim top bar, the lines in a 2×2 grid, and PLAY in normal flow.
- `navScope()` in `08b-pad.js` includes `setupSheet` for controller focus.

**Locker, light touch (`20-locker-ui.js`):**
- Cases you hold sort first.
- Empty cases get the `.cbox.empty` class: a one-line description, BUY only. The OPEN button stays in the DOM but is hidden by CSS, because tests look for it.
- Milestones: each ladder's tiles sit in a `.msRow` strip that scrolls sideways on phones, with an "n / 5 unlocked" count in the header.

**Settings:**
- `#pg-settings .cards` uses CSS columns, so cards stack without gaps.
- Slider thumbs are bigger.

**CSS:** all new rules are in the blocks appended at the end of `dev/src/style.css`, starting at "v0.9.5 menu overhaul".

**Tests changed for v0.9.5.0:**
- Any click on a moved control now opens the sheet first, then clicks inside it, then DONE. The pattern is `[data-setup=job]:visible` → `#setupSheet [data-c=…]` → `#setupDone`. Use `:visible` or a container such as `#hostRows`/`#roomRows`, because `#homeRows` on the hidden PLAY page also matches.
- The affected tests: `solo`, `bosses`, `v087`, `rewards_lobby_shotgun`, `controller`, `multiplayer`, `blitz_network`, `netxl`, `v090_net`, `lobby` (section 4b rewritten for the sheet), `modifiers` (the room host now sets modifiers via `#roomRows [data-setup=mods]`), `skilltree` (it reads `#navSkills .nBadge`) and `delgado` (the new intro text).
- `run_all.sh` now fails on a non-zero exit. That exposed `v087`, which had been failing one check since v0.9.1 while reported as PASS: the end screen reads "+N shards from leftover salvage", no longer "from 120 leftover salvage". The check was updated.
- Two timing races were fixed:
  - `blitz_mode`: Delgado could revive the downed player at random. He is now parked across the map during that check.
  - `blitz_network`: the test now waits for the guest's HUD label to redraw.
